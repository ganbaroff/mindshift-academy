## 3A. Mandatory Implementation Corrections (CEO-approved 31.07.2026 — override any conflicting wording in W0-W5)
1. Migration baseline safety: prisma/migrations/0000_baseline/migration.sql is an immutable historical schema snapshot ONLY. It MUST NEVER be run against a non-empty database. Every production schema change requires: a read-only receipt of the LIVE Turso schema; a verified additive/idempotent delta generated from that live schema to the target (never from-empty); a rehearsal against a production-like copy; and an explicit rollback/forward-repair procedure validated on an isolated copy. Do not represent "CREATE TABLE from empty" as a rollback mechanism.
2. Privacy-safe degradation observability: replace the globally aggregated DegradeEvent with a minimal pseudonymous session-scoped event: fields eventId, opaqueSessionId (rotating/pseudonymous — NOT Clerk ID, NOT a permanent child profile ID), lessonId, providerStage, causeEnum, occurredDayBucket, resolvedByFallback (boolean), retentionUntil. Forbidden in this table: raw child input, prompt contents, AI response text, IP address, device fingerprint, precise timestamps. Rationale: this preserves privacy-by-design while enabling real reliability measurement (how many children hit fallback, whether fallback affects completion, whether one provider degrades the course).
3. Certificate recipient label: the V1 certificate defaults to "Участник MindShift V1". A parent MAY set an optional display label: max 32 characters, local validation + profanity/safety filter, never used as account identity, never sent to AI providers, never included in metrics/logs, revisable by the parent before issuance; no public verification page. The own-words formulation activity stores ONLY: submitted=true, content version, timestamp bucket, and deterministic completion state — NEVER the raw child text. The child may see/download their own formulation in the current session UI, but it is not persistent data.
4. Test-provider separation: all ordinary unit/integration/CI/E2E tests use a deterministic local fake AI provider and fixture-backed moderation/safety responses only. The fake provider must deterministically simulate: interpreter down, judge down, tutor down, moderation error — and prove the fallback paths. Live-provider smoke is a SEPARATE, manually approved test: synthetic fixtures only (never child data), strict token/cost ceiling, redacted logs, never part of ordinary CI, never stores request/response text.
