## 2. AI reactions to WRONG answers — PASS

For every lesson, a safe-but-off-task message: moderation passes (`safe=true`), the judge
correctly FAILS it (`pass=false`, no reward), and the tutor replies **in character** with a kind
nudge. The judge reason is specific and pedagogical, e.g.:

- L1 "не знаю что писать" → judge: *"попробуй описать монстра, используя хотя бы три разных качества."*
- L2 "привет как дела" → judge: *"это просто приветствие, а не инструкция о стиле речи."*
- L3 "расскажи анекдот" → judge: *"ты не задал правило для секретного кода."*
- L4 "какая погода" → judge: *"не относится к теме про машинное зрение."*
- L5 "я устал" → judge: *"нет логического условия, которое управляло бы поведением."*

## 4. BUG FOUND + FIXED — zero-reward modal on lesson-5 replay

**Symptom:** re-completing lesson 5 returned a non-null `rewardTotals` (`{xp:0,crystals:0}`),
which makes `modalShouldOpen()` true → the "Задание выполнено!" celebration fires again on a
replay, with **no reward actually granted**.

**Root cause:** L5's `nextStep` clamps at 5, so after finishing L5 the reward gate
(`serverStepId === activeStepId`) keeps firing on re-view. `updateUserRewards` hits its
anti-double-award guard (P2002) and returns `awarded:false`, but `route.ts` set `rewardTotals`
unconditionally — surfacing a non-null value even when nothing was granted. The regression suite
missed it because it *modelled* a replay as `rewardTotals:null`, which the live route did not
actually produce for L5.

**Fix** (`src/app/api/chat/route.ts`): surface `rewardTotals` only when `res.awarded` is true.
On a replay it is now null → no modal.

**Verified:** `scripts/qa-verify-l5-replay.mjs` — first completions L1→L5 still reward
(100→1200 xp); L5 replay now returns `rewardTotals=null`, `modalShouldOpen=false`. Build/lint/
`npm test` 14/14 / regression 21-0-1 all still green.

  reason in the chat on a failed attempt would tighten the loop. Low priority.
