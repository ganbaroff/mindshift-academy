## Named gaps — none of these are done

1. **The browser gate never runs in CI.** It needs `CLERK_SECRET_KEY` as an Actions secret.
   Without it the job reports BLOCKED (green, honest, certifies nothing). The founder must
   add it; an agent must not place secrets.
2. **`/map` has never been seen by an automated run.** It is a server component that asks
   Clerk directly and the e2e harness cannot authenticate into it. The founder confirmed it
   renders correctly by screenshot on 2026-08-10.
3. **The species picker and the growth celebration are not built.** `MonsterSVG` supports
   both; nothing calls them. A child cannot yet choose a species — one is derived from their
   existing colour by `speciesFromColor`.
4. **13 of 15 sessions have no task brief.** `w1-s1` and `w2-s1` are done as the reference.
   `validateSession` rejects a session briefed only halfway, so partial migration is safe.
   Authoring the rest is the founder's call per `docs/design-handoff/v1.1/07-PROJECT-ANSWERS.md`.
5. **Mood decay still runs.** `src/app/api/cron/mood-decay/route.ts` drops the monster's mood
   for missed days — the streak guilt this design promises not to inflict. Gets worse now
   that the monster visibly grows. Founder's decision.
6. **Four installed skills were never run:** `impeccable critique`, `find-animation-opportunities`,
   `animate`, `animation-vocabulary`. Suggested order for the next session: critique the map
   and the monster (nobody has reviewed them as UX), then look for animation opportunities on
   the map, which has none, then build the growth celebration with `animate`.
7. **`OPERATOR_ALERT_EMAIL` is now required in production env.** If it is unset, `check:prod-env`
   fails — deliberately: without it every access request and problem report is silently dropped.

## Two traps this session fell into — do not repeat

- A placeholder Clerk **publishable** key is worse than none: it encodes the instance host,
  so the middleware proxies to a domain that does not exist and the whole app answers 404.
- Injecting a fallback key into the e2e server's env overrides the real one from the env
  file, because Next only reads that file for variables the process does not already have.
  It broke the gate locally while appearing to fix CI.
